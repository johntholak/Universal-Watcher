# Job Seed Employers V1

## Purpose

This file turns `JOB_SEED_UNIVERSE_V1.md` into the first concrete employer candidate set for the Automated Job Hunter bootstrap.

It is intentionally split into two concepts:

1. **candidate employer priority** — companies worth covering early because they may produce direct, adjacent, transferable, local, or remote opportunities
2. **verified source coverage** — companies whose current supported ATS/provider identity has actually been confirmed

A company may be high priority while its provider/source remains unverified or unsupported by the first V1 adapters.

The candidate list is **not a whitelist**. Dynamic discovery may add any legitimate employer/source outside this file.

## Status vocabulary

- `verified_supported` — direct public source identity confirmed on a currently supported V1 provider family
- `direct_or_custom` — current official careers experience observed, but not yet mapped to a supported provider adapter
- `candidate_unverified` — employer belongs in the priority universe, but its current careers source has not yet been verified
- `deprioritized` — retained for history but intentionally lower priority

Provider/source status must be reverified during implementation. This document records a bootstrap checkpoint, not permanent provider truth.

## Coverage balancing rules

The seed should not be considered healthy merely because it contains many companies.

Measure representation across:

- direct events/experiential roles
- technical production/event technology
- media/entertainment/live experiences
- technology field/partner/customer events
- program/project/operations transfer roles
- Southern California
- US remote
- large employers
- mid-size/high-growth employers
- agency/vendor/service-provider employers

If one category dominates the verified source count, intentionally verify sources in the underrepresented lanes next.

## Discovery feedback rule

If a worthwhile role is manually found at an employer not represented here:

1. add the employer/company identity
2. discover and verify its public source
3. add it to the registry if valid
4. classify why the employer was missed
5. add a regression case if the miss exposed a systematic coverage problem

The list should improve from real-world misses rather than requiring periodic full manual rewrites.

## Core rule

This file is the first launch pad, not the boundary of search.

Job Hunter should eventually know far more employers than are listed here, and a great role at an unknown employer must be allowed to outrank a mediocre role at a famous seed company.
