# Universal Watcher Visual Design Baseline

Status: Approved product direction
Date: September 4, 2026

## Purpose

The approved visual mockups are the target for the finished Universal Watcher experience, not loose inspiration. The implemented product should closely match their visual quality, depth, hierarchy, density, and overall polish while remaining functional and responsive.

Primary visual reference:

- `docs/design/universal_watcher_movies_visual_reference.jpg`

## Shared visual language

Use this design language consistently across Home, Movies, Family Deals, Watches, and future approved modules:

- dark navy / near-black application background
- layered surfaces with visible depth rather than flat forms
- blue and purple as the primary interface accents
- green used selectively for success, verified matches, and positive Family Deals actions
- thin luminous borders and restrained glow around important cards and active states
- clear contrast between page background, section panels, controls, and result cards
- polished iconography and compact visual indicators
- substantial card layouts rather than plain form stacks
- consistent sidebar and top navigation treatment
- rounded corners and deliberate spacing
- strong section headings and numbered workflow steps where appropriate
- concise secondary text with lower contrast than primary labels
- clear primary action buttons with strong visual emphasis
- selected inputs, theaters, dates, formats, and other active states must be visually obvious
- results should feel integrated into the same premium visual system, not like a separate plain data table

## Movies-specific reference

The approved Movies mockup establishes the target structure and visual quality:

- persistent Universal Watcher navigation shell
- Movies header with icon and concise purpose statement
- numbered cards for Choose the Movie, Choose Where, Choose When, Seat Preferences, and More Options
- prominent search summary panel
- theater selection shown as a polished list with selected states and distances
- clear date/time controls and expandable advanced options
- large primary Search for Seats action
- secondary Save as Watch action
- rich search-result cards showing theater, format, showtimes, qualifying seats, match checks, and direct View Seats/Open AMC actions

The implementation may adapt spacing and stacking for different screen sizes, but should preserve the same information hierarchy and perceived quality.

## Product-wide rule

Do not allow implementation convenience to flatten the product into generic HTML forms, plain cards, or a cheaper approximation of the approved mockups.

If the site is functionally correct but visually feels materially flatter, cheaper, or less layered than the approved references, the design is not considered finished.

## Consistency rule

New screens should reuse the same visual system rather than inventing a new style per module. Module identity can come from iconography, imagery, and selective accent treatment, while typography, spacing, surfaces, navigation, control styling, and card behavior remain consistent.

## Function before decoration

Visual fidelity must not remove or hide important module functionality. Preserve the approved functional baselines first, then express them through this shared design language.
